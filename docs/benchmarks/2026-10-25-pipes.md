# Pipes baseline: 25 October 2026 (Linux)

Command: `uv run python -m pipes_problem.benchmark`.
All 90 runs solved. The [raw CSV](2026-10-25-pipes.csv) contains every run.
The [manifest](2026-10-25-pipes-manifest.json) includes exact maps/hashes,
settings, environment and per-run expansions. This rerun measures the same nine
default maps on the course Linux machine (the [22 October baseline](2026-10-22.md)
was recorded on macOS), so Pipes and Light Up numbers in the report share one
environment.

| Size | Algorithm | Solved/runs | Median time (ms) | Median peak allocation (KiB) |
|---|---|---:|---:|---:|
| 4×4 | DFS | 15/15 | 3.149 | 26.984 |
| 4×4 | Greedy Best-First | 15/15 | 3.097 | 12.359 |
| 5×5 | DFS | 15/15 | 5.261 | 53.297 |
| 5×5 | Greedy Best-First | 15/15 | 6.157 | 19.219 |
| 7×7 | DFS | 15/15 | 24.469 | 145.852 |
| 7×7 | Greedy Best-First | 15/15 | 31.695 | 27.594 |

Each group contains three distinct generated maps with five repeated runs each.
Both algorithms use the same inputs, fixed assignment order, pruning, a 30-second
computation limit and a 200,000-expansion limit. The summary includes successful
runs only. All runs in this batch succeeded.

Environment: Python 3.13.14, pygame-ce 2.5.8, Linux 6.8.0-138-generic x86_64.
Source hash: see `source_sha256` in the manifest.

DFS is faster than Greedy at 5×5 and on two of three 7×7 maps; Greedy is faster
on the hardest map (pipes-7x7-263: 38.2 vs 40.8 ms) and keeps 4–5× less traced
peak allocation. These maps remain easy under the shared pruning; see the report
for the full interpretation and its limitations.
